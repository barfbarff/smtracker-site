Train a segmentation model on outlines you've corrected, so the next folders need fewer corrections. You fine-tune Cellpose-SAM (or, run from source, an Omnipose model) on your own data, here if this computer can train, or on another machine such as Google Colab. Skip this page while the pretrained models or the classical segmenter outline your cells well enough.

Training happens in a separate window, **SMTracker · model trainer**. Click **Train a model** in the outlines window's sidebar, then <Ui variant="outline">Open the trainer</Ui>.

## What training needs

Training needs two things: outlines worth learning from, and a computer that can train.

- **Outlines to learn from.** The trainer uses every outline file in a condition's `cell_meshes/` folder that has a matching image, whether you corrected it or not, and its list calls them all *corrected*. So correct the fields in [Edit outlines](/docs/cell-outlines/edit-outlines) first, and remove the outline files of fields you haven't checked. Fields whose files hold no outlines are skipped.
- **To train here:** the [segmentation pack](/docs/install#automatic-cell-outlines) with GPU support and an NVIDIA graphics card with about 6 GB of memory or more. Cellpose-SAM is a large network: a 4 GB card runs out of memory, and SMTracker says so before it starts. Otherwise, build a training set and export it to a machine that can train, such as Google Colab. Fine-tuning an Omnipose model needs SMTracker run from source with Omnipose.

A note under the trainer's buttons says whether this computer can train, and if not, why. No minimum number of fields is established for this data; the build's summary says how many cells you're training on.

## Build and train a model

Train in six steps, from your conditions to a model in Segment's list.

<Steps>
<Step>
### Open the folder

The trainer opens on the outlines window's folder, if one is open. Otherwise click <Ui variant="outline">Open folder…</Ui> and choose the folder that holds your conditions. The trainer lists each condition with its number of fields, all selected. Clear the ones you don't want to train on.
</Step>
<Step>
### Choose what to train on

Leave **labels from** at *cell_meshes (what you corrected)*, and **images in** at *phase* for phase-contrast snapshots, or choose *sum* for the projections. The model then reads the same kind of image on Segment.
</Step>
<Step>
### Choose how to train

Leave **start from** at *bact_phase_omni* (or choose *bact_fluor_omni* for projections). Leave **hold out** at 0.2 and **epochs** at 100 for a first model.
</Step>
<Step>
### Build the training set

Click <Ui variant="outline">Build training set</Ui>. Its label also counts the fields of the selected conditions. SMTracker writes the images, labels and held-out fields into `training_set/` in the folder you opened, and the trainer's log summarizes what's in it.

The settings are fixed when you build. If you change one afterward, build again.
</Step>
<Step>
### Train

Click <Ui variant="outline">Train here</Ui> if this computer can train. The log says when it has started and when it's done, with the path of the new model file, under `training_set/models/`. There's no progress bar and no per-epoch output, and a run can't be stopped.

Otherwise, click <Ui variant="outline">Export to…</Ui> and choose a folder, for example on Google Drive. The exported `training_set/` holds its own `train.py`, a README and a Colab notebook, and doesn't need SMTracker. Train there, then download the model file.
</Step>
<Step>
### Add the model to SMTracker

Click <Ui variant="outline">Save a model file…</Ui> and choose the trained model file. Type a name, and a short description of what it's for, when SMTracker asks. SMTracker copies the model into its model store: `%APPDATA%\SMTracker\models` on Windows, or `~/.config/smtracker/models` on macOS and Linux.

Then open the folder again in the outlines window. The model appears in each condition's **Model** list on Segment, as *(trained, reads phase)* or *(trained, reads sum)*.
</Step>
</Steps>

To remove a saved model, select it in the trainer's list of saved models and click <Ui variant="outline">Delete</Ui>. SMTracker asks first, then deletes it from the store.

Training doesn't add a model anywhere by itself: until you save it, it only exists as a file in `training_set/models/`.

<Callout type="check">
**Save a model file…** records what the model reads from the training set built in this trainer session. If you trained elsewhere and haven't built the same set again in this session, the model is listed as *(trained, reads phase)*, even if it was trained on projections. Build the same training set again before you save it.
</Callout>

## The settings

| Setting | What it does | Default |
| --- | --- | --- |
| **labels from** | Where the labels come from: *cell_meshes (what you corrected)*, the outline files, or *masks/ (label images)*, images in a `masks/` folder where each cell's pixels hold its own number. | *cell_meshes (what you corrected)* |
| **images in** | The folder of images the model learns from, and later reads on Segment: *phase*, *sum*, or any folder name you type. With *phase* and no `phase/` folder, the snapshots beside the movies are used. | *phase* |
| **start from** | The model to fine-tune: *bact_phase_omni*, *bact_fluor_omni*, or *: train a NEW model from scratch:*. Fine-tuning never changes the starting model; it writes a new file. | *bact_phase_omni* |
| **hold out** | The share of fields kept out of training, from 0 to 0.5, so the new model can be compared with its starting model on fields neither has seen. With two or more fields, at least one is always held out; with one field, none is. | 0.2 |
| **epochs** | How long to train, from 1 to 2000. | 100 |

Fine-tune rather than train from scratch. Cellpose suggests a new model needs far more labeled images than a fine-tune, hundreds rather than tens.

## Check the new model

The trainer doesn't score a model itself, so every model saved from it is listed as *not scored against its base model*. To compare the new model with its starting model, segment a few fields you didn't train on with both models, and compare them in [Edit outlines](/docs/cell-outlines/edit-outlines). The exported Colab notebook also has a scoring cell, for fine-tuned models.

## Limits of the trainer

The trainer has a few rough edges. Work around them like this:

- It finds conditions one level below the folder you open. Open the folder directly above your conditions, not a condition itself or a folder two levels up.
- Building again writes into the same `training_set/` without clearing it, so images, held-out fields and models from an earlier build stay, and are trained on. Delete `training_set/` before you build a smaller set. **Export to…** also merges into an earlier export.
- Closing the trainer while it trains freezes the window until the training has finished.
